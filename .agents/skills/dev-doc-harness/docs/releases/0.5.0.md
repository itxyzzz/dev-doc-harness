# Dev Doc Harness 0.5.0

## Release

Dev Doc Harness `0.5.0` hardens large and phased planning, improves work-item artifact structure, adds portable validation, and documents the release-branch preparation flow.

## Package Contents

The distributable package is root `AGENTS.md` plus `.agents/`.

It does not include this repository's `docs/work-items/`, root `README.md`, root `CHANGELOG.md`, root `TODO.md`, `.git/`, or local development files.

## Added

- Added first-class architecture-decision guidance for work-item snapshots.
- Added artifact-style guidance for crisp, durable specs, plans, snapshots, amendments, and variance logs.
- Added modular template block assembly tooling and manifests.
- Added a portable Python harness validator.
- Added release branch preparation guidance as the source for future branch cuts.

## Changed

- Clarified anchor-spec-first orchestration for large phased planning.
- Aligned large-work sizing guidance with phased template requirements.
- Improved small and medium spec and plan template scaffolding.
- Centralized naming convention rules and reduced duplicated naming guidance.
- Required implementation completion to end in a commit or an explicit blocker.
- Grouped changelog entries by release-oriented sections.

## Repository-Only Changes

- Documented the repository-local release branch process, including release-branch derivation, package-local release notes, branch push, and post-release development marker reset.

## Compatibility

Harness release versions carry compatibility meaning.

Stable `module:*`, `rule:*`, and `schema:*` IDs remain unversioned anchors.

## Team Adoption

Copy root `AGENTS.md` and `.agents/` into the target repository, merge local `AGENTS.md` instructions carefully, run validation when practical, and commit the harness update separately from product work.

## Rollback

Revert the dedicated harness update commit or PR to restore the previous root `AGENTS.md` and `.agents/` package.
