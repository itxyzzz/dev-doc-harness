# Dev Doc Harness 0.5.0

## Release

Dev Doc Harness `0.5.0` improves planning artifact readability, release branch execution, template maintainability, work-item architecture capture, naming consistency, validation portability, and phase orchestration guidance.

## Package Contents

The distributable package is root `AGENTS.md` plus `.agents/`.

It does not include this repository's `docs/work-items/`, root `README.md`, root `CHANGELOG.md`, root `TODO.md`, `.git/`, or local development files.

## Added

- Added `module:artifact-style` for final artifact content, scannable structure, placeholder control, traceability density, and template prompt style.
- Added first-class work-item architecture decision support, including lifecycle, quality, router, template, documentation, validator coverage, and the reusable `architecture-snapshot.md` template.
- Added canonical naming convention guidance for work-item IDs, artifact filenames, commit subjects, changelog entries, collision handling, and title normalization.
- Added ordered template source blocks, assembly manifests, `assemble_templates.py`, and validation coverage so planning templates remain generated and self-contained.
- Added `rule:lifecycle.large-phase-orchestration` as the lifecycle-owned state sequence for large/phased planning.

## Changed

- Updated small/medium spec and plan templates with stronger source/intent, scope, context, traceability, validation, task dependency, sub-agent strategy, and readiness prompts.
- Updated large/phased spec and phase-plan templates to preserve anchor-spec-first planning, fresh-thread phase execution, and improved small/medium structure.
- Replaced repeated naming grammar across current lifecycle, freeze-gate, quality, template, operator-facing, and validation surfaces with references to the naming owner.
- Clarified implementation completion so agents must commit completed implementation work or report the exact blocker or explicit no-commit instruction.
- Replaced the PowerShell-only harness validator with a Python standard-library validator and updated validation guidance accordingly.
- Grouped the root changelog by release and updated validator coverage for release-grouped changelog sources.
- Clarified stable release-note filename handling so `VERSION` can use a post-release development marker such as `0.5+` without requiring a separate `+.md` release-note file.

## Repository-Only Changes

- Added a root-level agent-executable release branch runbook and an `AGENTS.md` pointer for chat-triggered release branch creation, release-note curation, release branch push, and post-release `master` reset.
- Added a root-local non-mutating pre-commit hook for harness repository development.

## Compatibility

Harness release versions carry compatibility meaning.

Stable `module:*`, `rule:*`, and `schema:*` IDs remain unversioned anchors.

## Team Adoption

Copy root `AGENTS.md` and `.agents/` into the target repository, merge local `AGENTS.md` instructions carefully, run validation when practical, and commit the harness update separately from product work.

## Rollback

Revert the dedicated harness update commit or PR to restore the previous root `AGENTS.md` and `.agents/` package.
