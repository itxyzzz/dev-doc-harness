# Dev Doc Harness 0.7.0

## Release

Dev Doc Harness `0.7.0` improves plain-language planning guidance, calibrates the active economy-default model policy, and makes multi-entry changelog fragments safer to validate and consolidate for releases.

## Package Contents

The distributable package is root `AGENTS.md` plus `.agents/`.

It does not include this repository's `docs/work-items/`, root `README.md`, root `CHANGELOG.md`, root `TODO.md`, `.git/`, or local development files.

## Added

- Added entry-scoped changelog fragment parsing and a grammar-only `--lint` gate before release consolidation.

## Changed

- Added a canonical plain-language rule, required its style module for small/medium planning, and aligned concise template prompts and route cues with focused validation.
- Calibrated the `economy-default` model-selection guidance, supporting reviewer examples, model-strategy prompts, generated templates, and policy checks.
- Retained independent sub-agent review as the default, with separate task or thread review kept as an operator-managed fallback until inter-task reporting is proven.
- Updated ordinary commit, release preparation, and operator guidance so root changelog consolidation remains a checkpoint-owned step.

## Compatibility

Harness release versions carry compatibility meaning.

Stable `module:*`, `rule:*`, and `schema:*` IDs remain unversioned anchors.

## Team Adoption

Copy root `AGENTS.md` and `.agents/` into the target repository, merge local `AGENTS.md` instructions carefully, run validation when practical, and commit the harness update separately from product work.

## Rollback

Revert the dedicated harness update commit or PR to restore the previous root `AGENTS.md` and `.agents/` package.
