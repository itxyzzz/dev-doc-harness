# Dev Doc Harness 0.6.0

## Release

Dev Doc Harness `0.6.0` strengthens conformance-oriented planning, model and task-handoff guidance, changelog release preparation, Superpowers compatibility, and operator-facing documentation.

## Package Contents

The distributable package is root `AGENTS.md` plus `.agents/`.

It does not include this repository's `docs/work-items/`, root `README.md`, root `CHANGELOG.md`, root `TODO.md`, `.git/`, or local development files.

## Added

- Added canonical Specification Commitment, Verification Criterion, Implementation Task, and Plan Check guidance with traceability, conformance, and validation coverage.
- Added independent model-selection dimensions, explicit orchestration and fallback boundaries, and artifact-grounded task-handoff guidance.
- Added work-item-local changelog source fragments and a duplicate-safe consolidation command for release preparation.
- Added explicit continuity-task creation and planning-shape handoff guidance across primary templates.

## Changed

- Replaced checklist-shaped plan prompts with sectioned task blocks and centralized requirement and acceptance traceability guidance.
- Updated Superpowers compatibility so continuity pointers require pre-existing historical packages and remain minimal stubs.
- Updated operator-facing documentation with clearer problem framing, ordinary conversational use, and protected post-release synchronization guidance.
- Aligned the release policy, validator, and release notes with the concrete `0.6.0` release identity.

## Removed

- Removed the repository's six current Superpowers compatibility pointer stubs.

## Repository-Only Changes

- Added a protected post-release synchronization process and remote verification before later development branches begin.

## Compatibility

Harness release versions carry compatibility meaning.

Stable `module:*`, `rule:*`, and `schema:*` IDs remain unversioned anchors.

## Team Adoption

Copy root `AGENTS.md` and `.agents/` into the target repository, merge local `AGENTS.md` instructions carefully, run validation when practical, and commit the harness update separately from product work.

## Rollback

Revert the dedicated harness update commit or PR to restore the previous root `AGENTS.md` and `.agents/` package.
